# گزارش نهایی آماده‌سازی انتشار نوین‌نت

**تاریخ تهیه:** ۲۲ اوت ۲۰۲۶  
**دامنه:** سایت عمومی، پنل کاربر و پنل ادمین  
**اصل اجرا:** ظاهر، مسیرهای نمایشی و ساختار ماژولار موجود حفظ شده‌اند. اصلاحات فقط به منطق، اتصال داده، اعتبارسنجی، امنیت و آماده‌سازی انتشار مربوط هستند.

## جمع‌بندی اجرایی

نسخهٔ حاضر از حالت وابسته به داده‌های نمایشی در بخش‌های کلیدی خارج شده است. APIهای واقعی برای سبد خرید، سفارش، پروفایل، نشانی‌ها، علاقه‌مندی‌ها، تیکت‌ها، کیف پول، نشست‌ها، کدهای تخفیف و تنظیمات ایجاد یا تکمیل شدند. پنل ادمین نیز برای محصولات، دسته‌بندی‌ها، سفارش‌ها، کاربران، کیف پول، تیکت‌ها، کوپن‌ها و تنظیمات به API متصل شد؛ بدون تغییر در طراحی صفحات یا تجربهٔ کاربری.

> **نتیجه:** تمام ایرادهای داخلیِ قطعی که در ممیزی کد قابل بازتولید بودند، رفع یا به رفتار ایمن تبدیل شده‌اند. موارد وابسته به اطلاعات و سرویس‌های خارجی، مانند شناسهٔ پذیرندگی پرداخت، سرویس‌دهندهٔ پیامک و دیتابیس سرور، عمداً با دادهٔ ساختگی فعال نشده‌اند و پیش از بهره‌برداری باید پیکربندی شوند.

| حوزه | اصلاحات اصلی | وضعیت |
| --- | --- | --- |
| سایت و خرید | سبد مهمان، ادغام سبد پس از ورود، checkout، پاسخ‌های پرداخت در انتظار و حفظ مالکیت سفارش | آمادهٔ اتصال به سرویس پرداخت |
| پنل کاربر | پروفایل، آدرس، سفارش، علاقه‌مندی، تیکت، کیف پول و نشست‌های فعال | متصل به API |
| پنل ادمین | CRUD محصول و دسته، سفارش و رهگیری، کاربر و کیف پول، تیکت، کوپن و تنظیمات | متصل به API |
| امنیت و استقرار | حذف ورود و دادهٔ نمایشی در production، پاسخ استاندارد ۴۰۱/۴۰۳، cache و فایل‌های محیط | آمادهٔ staging |

## اصلاحات مهم انجام‌شده

### سایت و پنل کاربر

منطق سبد خرید از دادهٔ محلی جدا شده و در production از API استفاده می‌کند. سبد مهمان با یک شناسهٔ پایدار ایجاد می‌شود و هنگام ورود با سبد حساب کاربر ادغام می‌گردد تا کالای انتخاب‌شده از دست نرود. برای این سناریو یک آزمون مستقل اضافه شده است.

ثبت سفارش دیگر به‌اشتباه «پرداخت موفق» نشان داده نمی‌شود. پس از ایجاد سفارش، رابط وضعیت آن را «در انتظار پرداخت» نمایش می‌دهد. درگاه آزمایشی فقط برای محیط آزمایش نگاشت شده و شبیه‌سازی پرداخت در production به‌صورت پیش‌فرض غیرفعال باقی می‌ماند.

مجموعهٔ APIهای کاربر شامل علاقه‌مندی، تیکت و مکاتبه، درخواست شارژ کیف پول در وضعیت pending، نشست‌های فعال و خاتمهٔ نشست‌های دیگر است. تعدیل اعتبار کیف پول فقط از طریق پنل ادمین و با ثبت تراکنش انجام می‌شود؛ هیچ افزایش اعتبار نمایشی در production باقی نمانده است.

### پنل ادمین

فهرست محصولات و دسته‌بندی‌ها در پنل ادمین اکنون شامل موارد غیرفعال نیز می‌شود، در حالی که سایت عمومی همچنان فقط موارد فعال را نشان می‌دهد. ایجاد، ویرایش، حذف، وضعیت فعال، ویژه‌بودن و موجودی محصول به endpointهای محافظت‌شده متصل شده‌اند. تغییر موجودی در جدول inventory ذخیره می‌شود.

عملیات سفارش به API واقعی متصل شده و برای ثبت کد رهگیری یک migration و فیلد `tracking_code` اضافه شده است. حذف سفارش در production به‌طور آگاهانه مجاز نیست تا سابقهٔ مالی از بین نرود؛ رابط به‌جای حذف نمایشی، مدیر را به تغییر وضعیت سفارش هدایت می‌کند.

عملیات نقش و وضعیت کاربر، تعدیل کیف پول، پاسخ و تغییر وضعیت تیکت، کدهای تخفیف و تنظیمات فروشگاه از localStorage جدا شده‌اند. وضعیت‌ها و مدل پیام‌های تیکت در کامپوننت ادمین نیز با API واقعی هم‌راستا شده‌اند.

## پیش‌نیازهای باقی‌مانده برای سرور واقعی

این موارد «اشکال کد» نیستند، بلکه اطلاعات و سرویس‌های خارجی هستند که در فایل ارسالی وجود نداشتند. فعال‌سازی ساختگی آن‌ها انجام نشده است.

| مورد | اقدام لازم پیش از production |
| --- | --- |
| دیتابیس | مقادیر واقعی `DB_*` را در `.env` سرور قرار دهید، سرویس MySQL/MariaDB را در دسترس کنید و `php artisan migrate --force` را اجرا کنید. بررسی محلیِ وضعیت migration به دلیل اتصال ردشده به MySQL محلی انجام نشد؛ کل migrationها در محیط آزمون SQLite اجرا شدند. |
| پرداخت واقعی | یک درگاه پشتیبانی‌شده را با کلیدهای واقعی پیکربندی و callback HTTPS را روی دامنهٔ نهایی ثبت کنید. زرین‌پال برای ایجاد درخواست، هدایت کاربر با authority و تأیید سمت‌سرور پس از بازگشت کاربر، به `merchant_id` و callback نیاز دارد.[1] [2] |
| پیامک واقعی | یک سرویس‌دهندهٔ پیامک و کلیدهای آن را در سرور تعریف کنید. ارسال ساختگی در production عمداً غیرفعال شده است. |
| دامنه و HTTPS | `APP_URL` و `VITE_API_BASE_URL` را با دامنهٔ نهایی و HTTPS تنظیم کنید. |
| صف و cron | در صورت استفاده از اعلان‌ها یا کارهای پس‌زمینه، worker صف و scheduler را در سرور فعال کنید. |

## ترتیب پیشنهادی استقرار

ابتدا محتویات بسته را روی سرور قرار دهید و فایل `.env.example` را به `.env` کپی کنید؛ مقادیر محرمانه را فقط در `.env` سرور قرار دهید. سپس وابستگی‌های PHP را با `composer install --no-dev --prefer-dist --optimize-autoloader` و وابستگی‌های رابط را با `pnpm install --frozen-lockfile` نصب کنید. بعد از تنظیم دیتابیس، `php artisan key:generate`، `php artisan migrate --force` و `pnpm build` را اجرا کنید. در پایان، مالکیت `storage` و `bootstrap/cache` را برای کاربر وب‌سرور تنظیم و cacheهای Laravel را ایجاد کنید.

## اقلام تحویلی

این پوشه شامل کد اصلاح‌شده، migrationهای جدید، آزمون‌های جدید، فایل‌های قفل وابستگی، راهنمای انتشار پیشین و همین گزارش است. فایل `.env`، پوشه‌های وابستگی محلی و داده‌های حساس در بستهٔ انتشار قرار نگرفته‌اند.
