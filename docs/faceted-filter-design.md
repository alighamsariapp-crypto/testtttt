# طرح فیلترهای دسته‌محور فروشگاه نوین‌نت

## تصمیم اصلی

فیلتر فروشگاه نباید مجموعه‌ای ثابت از گزینه‌ها برای همهٔ کالاها باشد. هر صفحهٔ دسته فقط باید **ویژگی‌هایی را نمایش دهد که برای همان نوع کالا معنا دارند و دست‌کم یک کالای موجود در آن scope مقدار معتبر برای آن دارد**. در نتیجه، صفحهٔ «لپ‌تاپ» با «موبایل»، «مودم» و هر برگ از «لوازم خانگی» متفاوت است؛ اما رفتار، ظاهر، URL و قواعد انتخاب آن‌ها یکپارچه می‌ماند.

بررسی صفحات فعلی تکنولایف نشان می‌دهد که category لپ‌تاپ فیلترهای مشترک مانند موجودی، قیمت و برند را با مشخصات تخصصی همچون RAM، نوع پنل، اندازهٔ نمایشگر، CPU، GPU، SSD، کاربرد و رنگ ترکیب می‌کند؛ همین دسته با انتخاب برند ایسوس، برند را از فهرست facetها حذف کرده و بقیهٔ فیلترهای تخصصی را حفظ می‌کند.[1] [2] این الگو با تصمیم قبلی نوین‌نت مبنی بر مستقل بودن **دسته** و **برند** هم‌راستا است.[3]

> **قاعدهٔ نوین‌نت:** دسته تعیین می‌کند «چه چیزی» فروخته می‌شود؛ برند و مشخصات تعیین می‌کنند «کدام مدل» به کاربر نمایش داده شود. برند هیچ‌گاه فرزند درخت دسته‌بندی نیست.

| لایه | وظیفه | نمونه |
|---|---|---|
| دسته | محدودهٔ نتایج و صفحهٔ SEO | لپ‌تاپ ← لپ‌تاپ گیمینگ |
| فیلتر مشترک | محدودسازی قابل‌اعمال برای هر کالای قابل‌خرید | موجودی، قیمت، برند، رنگِ واقعی |
| facet تخصصی | ویژگی‌های قابل‌فیلتر همان نوع کالا | RAM برای لپ‌تاپ؛ ظرفیت برای ماشین لباسشویی |

## تجربهٔ کاربر در صفحهٔ دسته

در بالای صفحهٔ دسته، ابتدا breadcrumb، نام دسته و زیردسته‌های مستقیم به صورت chip فشرده می‌آیند. نوار برند فقط در صورتی نشان داده می‌شود که برای scope فعلی دست‌کم دو برند واقعی وجود داشته باشد؛ این نوار یک **میان‌بر** است، نه فیلتر جداگانه. انتخاب برند در نوار دقیقاً همان انتخاب در بخش «برند» فیلتر است و باید وضعیت آن‌ها همگام باشد.

در desktop، sidebar ثابت سمت راست به ترتیب «فقط موجود»، «قیمت»، «برند»، سپس facetهای اولویت‌دار دسته را نشان می‌دهد. هر گروه accordion است، گزینه‌های صفرنتیجه پنهان می‌شوند و برای برندها یا گزینه‌های بلند، جست‌وجوی داخلی ارائه می‌شود. بالای گرید فقط chipهای انتخاب‌شده و دکمهٔ «پاک‌کردن همه» می‌آیند؛ فیلترهای انتخاب‌شده نباید دوباره به شکل کارت یا باکس بزرگ تکرار شوند.

در mobile، نوار کوتاه پایین یا بالای لیست فقط دو اقدام دارد: **فیلتر (تعداد انتخاب‌ها)** و **مرتب‌سازی**. فیلتر در bottom sheet تمام‌عرض باز می‌شود. «موجودی»، «محدودهٔ قیمت» و «برند» در ابتدای sheet قرار دارند و بقیهٔ facetها با accordion نمایش داده می‌شوند. footer ثابت شامل «پاک کردن» و «نمایش N محصول» است. هیچ drawer باریک کناری، فهرست بازِ طولانی یا کارت درشت برای دسته‌بندی استفاده نمی‌شود.

| رفتار | قاعدهٔ قطعی |
|---|---|
| انتخاب چند گزینه در یک facet | **OR**؛ مثل RAM برابر ۸ یا ۱۶ گیگابایت |
| انتخاب بین facetهای مختلف | **AND**؛ مثل RAM ۱۶ و SSD یک ترابایت |
| قیمت | بازهٔ حداقل/حداکثر؛ فقط بر پایهٔ قیمت فروش فعلی variant قابل‌خرید |
| رنگ | فقط رنگ‌هایی که variant موجود دارند؛ انتخاب رنگ باید تصویر همان variant را هم در کارت و صفحهٔ کالا هماهنگ کند |
| شمارش کنار گزینه | شمار نتیجه در scope فعلی و با حذف موقت همان facet محاسبه می‌شود تا کاربر بداند انتخاب بعدی چه اثری دارد |
| URL | پایدار، قابل refresh و قابل اشتراک؛ نمونه: `/store/laptops?brand=asus&ram=16gb,32gb&price_max=90000000` |
| گزینهٔ بدون داده | هرگز نمایش داده نمی‌شود؛ «فیلتر ساختگی» نداریم |

## فیلترهای مشترک همهٔ دسته‌ها

این چهار گروه فقط در صورتی نشان داده می‌شوند که دادهٔ معتبرشان در نتایج وجود داشته باشد:

| اولویت | فیلتر | نوع کنترل | منبع داده |
|---|---|---|---|
| ۱ | فقط کالاهای موجود | switch | موجودی واقعی محصول یا variant |
| ۲ | محدودهٔ قیمت | slider و ورودی عددی | قیمت فروش واقعی variant یا محصول |
| ۳ | برند | rail فشرده + checkbox جست‌وجوپذیر | برند مستقل محصول |
| ۴ | رنگ | swatch با نام رنگ | variantهای قابل‌خرید یا attribute محصول |
| ۵ | تخفیف / ارسال ویژه / گارانتی | switch یا checkbox | فقط وقتی backend واقعاً این داده را دارد |

امتیاز، «محبوب‌ترین» یا ادعاهای فروشنده تا زمانی که دادهٔ واقعی، قابل‌اعتماد و قابل‌محاسبه ندارند در فیلتر وارد نمی‌شوند. ترتیب فعلی نتایج می‌تواند شامل پرفروش، جدیدترین، ارزان‌ترین و گران‌ترین بماند، اما «محبوب‌ترین» تنها پس از داشتن دادهٔ واقعی بازخورد یا فروش فعال می‌شود.

## پروفایل فیلتر برای دسته‌های فعلی

هر نوع کالا یک **پروفایل فیلتر** دارد. category والد می‌تواند پروفایل را به فرزندان به ارث بدهد و هر فرزند فقط ترتیب یا ویژگی‌های خود را اضافه/پنهان کند. «لوازم خانگی» و «لوازم جانبی» در سطح والد فقط فیلترهای مشترک و انتخاب زیردسته دارند؛ فیلتر تخصصی همیشه متعلق به برگ واقعی است.

| دسته / برگ | فیلترهای اولویت‌دار | فیلترهای تکمیلی در accordion |
|---|---|---|
| **لپ‌تاپ و کامپیوتر** | برند، نوع کاربری، خانوادهٔ CPU، RAM، ظرفیت SSD، GPU، اندازهٔ نمایشگر | نوع پنل، رزولوشن، نرخ نوسازی، لمسی، وزن، سیستم‌عامل، اثرانگشت، چرخش ۳۶۰ درجه، نوع باتری، سری محصول |
| **لپ‌تاپ گیمینگ** | GPU، CPU، RAM، SSD، نرخ نوسازی، اندازهٔ نمایشگر | نوع پنل، وزن، نور صفحه‌کلید، درگاه‌ها، ظرفیت باتری |
| **اولترابوک و اداری** | وزن، اندازهٔ نمایشگر، CPU، RAM، SSD، عمر باتری | پنل، لمسی، سیستم‌عامل، اثرانگشت، چرخش ۳۶۰ درجه |
| **موبایل** | برند، حافظهٔ داخلی، RAM، شبکهٔ 5G/4G، اندازهٔ نمایشگر، رنگ | نرخ نوسازی، دوربین اصلی، ظرفیت باتری، تعداد سیم‌کارت، eSIM، سیستم‌عامل، NFC، مقاومت در برابر آب |
| **مودم و اینترنت** | برند، نسل شبکه، نوع اتصال، پشتیبانی سیم‌کارت، استاندارد Wi‑Fi | تعداد پورت LAN، نوع آنتن، پشتیبانی VoLTE، باتری، درگاه USB، قابلیت مش/Bridge |
| **تجهیزات شبکه** | نوع تجهیز، تعداد پورت، PoE، سرعت پورت، استاندارد Wi‑Fi | managed/unmanaged، تعداد آنتن، رک‌مونت، نوع uplink، قابلیت VLAN |
| **لوازم جانبی موبایل** | نوع کالا، سازگاری با برند/مدل، نوع اتصال، رنگ | توان شارژ، طول کابل، نوع کانکتور، جنس، مقاومت در برابر ضربه/آب |
| **لوازم جانبی لپ‌تاپ** | نوع کالا، سازگاری اندازهٔ دستگاه، نوع اتصال، برند | توان شارژ، تعداد پورت، طول کابل، نورپردازی، ارگونومی |
| **یخچال و فریزر** | نوع دستگاه، گنجایش، رتبهٔ انرژی، رنگ، بدون برفک | عرض/عمق/ارتفاع، آب‌سردکن، یخ‌ساز، کمپرسور، نوع درب |
| **ماشین لباسشویی** | ظرفیت، نوع درب، رنگ، رتبهٔ انرژی، دور موتور | موتور، تعداد برنامه، بخارشوی، ابعاد، قابلیت اتصال هوشمند |

دستهٔ سیم‌کارت در این مرحله وارد این پروفایل‌ها نمی‌شود؛ در صورت فعال‌سازی مستقل آن، filter schema آن باید جداگانه بر پایهٔ اپراتور، دائمی/اعتباری، پیش‌شماره، رندبودن، وضعیت مالکیت و بازهٔ قیمت طراحی شود.

## مدل no-code در پنل ادمین

مدیر نباید برای ساخت دستهٔ «یخچال» یا «هدفون» به برنامه‌نویس نیاز داشته باشد. در صفحهٔ ویرایش دسته یک tab با نام **ویژگی‌ها و فیلترها** اضافه می‌شود. مدیر یک پروفایل را انتخاب می‌کند، آن را clone می‌کند یا ویژگی جدید می‌سازد. سپس همان فیلدها در فرم ثبت کالا ظاهر می‌شوند و فقط فیلدهایی که `قابل‌فیلتر` هستند به storefront می‌روند.

| فیلد تعریف ویژگی در پنل | نمونه | اثر در storefront |
|---|---|---|
| کلید فنی یکتا | `ram_gb` | URL و query پایدار |
| عنوان فارسی | حافظهٔ RAM | عنوان accordion |
| نوع مقدار | انتخاب چندتایی، عددی، بازه، boolean، رنگ | نوع کنترل درست |
| واحد | گیگابایت، اینچ، کیلوگرم | نمایش و مقایسه درست |
| گزینه‌های مجاز | ۸، ۱۶، ۳۲ | جلوگیری از دادهٔ نامنظم |
| قابل‌فیلتر / نمایش در کارت | فعال یا غیرفعال | کنترل مستقل جست‌وجو و کارت محصول |
| اولویت و inherit | ۱۰، ارث به فرزند | ترتیب قابل مدیریت بدون کد |

برای برند نیز باید به‌مرور یک catalog مستقل شامل `نام، slug، لوگو، وضعیت فعال` تعریف شود. محصول به یک برند از این catalog متصل می‌شود؛ فیلترها، URL، rail برند و صفحهٔ برند از همان مرجع خوانده می‌شوند. تا زمان این تغییر backend، مقدار `attributes.brand` می‌تواند دادهٔ گذار باشد، اما برای مقیاس حرفه‌ای مرجع نهایی نیست.

### شکل دادهٔ پیشنهادی

```json
{
  "key": "ram_gb",
  "label": "حافظه RAM",
  "type": "multi_select",
  "unit": "GB",
  "options": ["8", "16", "32"],
  "filterable": true,
  "display_order": 30,
  "inherit_to_children": true
}
```

محصول پس از انتخاب category فقط مقدارهای مربوط به همان schema را ثبت می‌کند:

```json
{
  "brand": "asus",
  "ram_gb": "16",
  "ssd_gb": "512",
  "cpu_family": "core-i7",
  "display_size_inch": 15.6
}
```

## قرارداد backend موردنیاز در مرحلهٔ اجرا

این سند فقط طراحی است؛ اکنون هیچ migration یا API جدیدی اجرا نمی‌شود. اجرای کامل نیازمند ایجاد definitionهای ویژگی، اتصال آن‌ها به category، اعتبارسنجی مقادیر محصول و endpoint catalog است که هم **نتایج** و هم **facet counts** را از دادهٔ واقعی برگرداند. فیلتر در مرورگر نباید تنها بر چند محصول بارگذاری‌شده اعمال شود.

| لایه | تغییر موردنیاز در مرحلهٔ اجرا |
|---|---|
| دیتابیس | تعریف ویژگی، گزینه، اتصال category↔ویژگی و در مرحلهٔ حرفه‌ای catalog برند |
| فرم ادمین | رندر پویا از schema دسته و validation مقدارها |
| API catalog | ورودی filterهای typed، نتایج paginated، facetهای موجود و count هر گزینه |
| storefront | تبدیل URL به فیلتر، نمایش facetهای response و نگهداری انتخاب‌ها در refresh/back/forward |
| عملکرد | index روی category و brand؛ برای حجم بالا index یا جدول value جدا برای attributeهای پرتکرار |

## ترتیب اجرای پیشنهادی

ابتدا پروفایل‌های **لپ‌تاپ، موبایل و مودم** پیاده‌سازی و با چند محصول واقعی ادمین تست می‌شوند. سپس «لوازم جانبی» و هر برگ از «لوازم خانگی» با همان editor بدون کدنویسی اضافه می‌شود. این ترتیب هم سریع‌ترین ارزش را برای کالاهای فعلی می‌دهد و هم از ساختن فیلترهای نمایشیِ بدون داده جلوگیری می‌کند.
